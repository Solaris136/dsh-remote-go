> 版本 v0.6 · 2026-11-10 · 状态：内容设计稿（产品决策已确认；补充同类项目调研与远端自举/运维管理）

## 0. 摘要

**方向**：按 VS Code Remote-SSH 的思路做——**运行时整体留在服务器，本地只做「连接 + 窗口 + 状态」三件事**。

- 本地插件内容只有 6 块：**主机清单、接入向导、远端窗口（呈现远端 DSH 界面）、连接状态与诊断、设置、可选的通知提醒**。
- 会话、审批、文件、终端、插件、凭据、日志——**全部在远端 DSH 自己的界面里完成**，本地不重做一套。
- 本地代码量以「天」计（V1 约 1–2 周含打磨），而不是 v0.2 全控制台方案的 7–9 周。

**一条关键结论（决定方案选型）**：DSH 目前**没有**「本地原生界面直连远端 Host」的产品化能力（`dsh-api-remotes` / `dsh-experimental-liveshare` 等现有 Remote 能力方向是反的：把本机 Host 分享给别的客户端）。所以「VS Code 那种同一套原生 UI 渲染远端数据」在 DSH 里没有现成开关；要做成那样，本地必须加一层桥接（会话映射 / 事件回灌 / 审批桥），本地工作量反而不小——那就是 v0.2 和 `dsh-remote-local-plugin` 走的路线。

**但 DSH 原生支持「全局面板」**：插件可以把一个面板注册到主区域并整页切换过去（和 DSH 自带「插件」页同一种形态），也可以做覆盖整个窗口的全屏层。因此最贴合「本地只渲染」的做法是：**把远端 DSH 自己的完整 Web 界面放进这个全局面板**，本地只负责 SSH 连接、窗口承载与状态。本版按这个方向设计，能力依据见 §7.0。

**v0.6 增补**：远端可在**没有环境**时用 `npx` 精确版本拉起 DSH（无 Node 则下载独立运行时）；远端版本与**本机一致**；本机关闭后远端可**继续存活**（按主机可配）；远端的**插件与设置**可在本机管理（Diff/备份/重启提示）。详见 §16。

**分期**：V1.0 全局面板整页 + 主机管理 + 诊断 + 自举/版本一致/存活策略 → V1.1 沉浸模式 + 多主机 + 通知桥 + 插件管理 + 无 Node 自举 → V1.2 设置管理/打磨 → V2 评估「原生渲染」增强。

## 1. 设计原则与 VS Code 对照

| 职责 | VS Code Remote-SSH | 本设计（DSH 远程视窗） |
|---|---|---|
| UI 呈现 | 本地 VS Code 界面 | 本地 DSH 的「远程视窗」全局面板承载**远端 DSH 自己的界面** |
| 运行时（agent/工具/模型/会话） | 远端 VS Code Server | 远端 DSH |
| 文件 / 终端 / 扩展 | 远端 | 远端（远端 DSH 界面自带） |
| 传输 | SSH | SSH |
| 本地保存什么 | 连接信息、最近打开、设置 | 主机清单、连接状态、窗口与显示设置 |
| 本地不做什么 | 不跑扩展宿主、不读远端文件 | 不实现会话/审批/文件/终端/DSH 管理界面 |

**三条原则**：

1. **能在远端做的，一律在远端做**：本地不复制远端已有能力。
2. **本地只保留三类内容**：连接（SSH/隧道）、呈现（全局面板/沉浸层）、状态（主机与连接状态）。
3. **远端 DSH 保持原版**：不要求服务器安装任何本插件专属组件；远端界面是什么样，本地就看到什么样。

## 2. 职责边界

| 本地插件 | 远端 DSH |
|---|---|
| 保存主机清单与连接配置 | 运行 agent 循环、工具、模型调用 |
| 建立/保持/重建 SSH 连接与隧道 | 持久化会话与事件 |
| 在本地全局面板里呈现远端 DSH 界面 | 渲染会话、审批、文件、终端、插件管理、设置、凭据、日志 |
| 显示连接状态、加载状态、错误与诊断 | 处理审批与提问、执行命令、读写文件 |
| 记住窗口模式、最近打开、语言、安全选项 | 版本升级、插件安装、凭据轮换（在远端界面里操作） |
| 可选：把远端提醒转成本机通知 | 提供"当前需要人处理"的状态 |

**明确不做（本地）**：不重写会话视图、不实现审批面板、不做文件浏览器/编辑器、不做终端、不做 DSH 管理页、不做多机任务编排界面。

## 4. 本地页面内容设计

### 4.1 主机清单（侧边栏「远程视窗」入口）

**目标**：一屏看到所有服务器，点一下就进去。

**内容**：

- 顶部：标题「远程视窗」+「添加主机」主按钮 + 刷新状态。
- 主机卡片：显示名、SSH 地址（用户名@主机:端口，可脱敏）、状态（未配置/连接中/已连接/断开/错误/受限）、远端 DSH 版本、上次打开时间。
- 卡片操作：打开（切换到远程视窗面板）、连接/断开、编辑、删除；错误时显示「诊断」。
- 汇总条：已连接 N / 总共 M；可选显示「有提醒的主机」。
- 最近打开区（P1）：最近 3 台，一键回到上次的视窗。

**空态**：「还没有服务器。添加一台，然后在本地窗口里直接使用它上面的 DSH。」+「添加第一台服务器」。

**异常态**：卡片顶部红色细条 + 一句原因（分类见 §8.4）+「诊断」。

### 4.2 接入向导（3 步）

**步骤 1 · SSH 信息**

- 显示名（默认取地址/别名）、SSH 地址或本机 SSH 配置别名、端口、用户名。
- 认证：使用 SSH Agent / 指定密钥文件 / 密码（仅本次，不保存）。
- 跳板机（可选）：选另一台已添加主机或填写地址。
- 提示：密码不保存、密钥不上传。

**步骤 2 · 连接测试**

- 进度：网络可达 → SSH 认证 → 主机指纹确认 → 读取系统信息。
- 首次连接展示主机指纹，要求确认；指纹变化时强提示。
- 失败按类提示：网络 / 认证 / 指纹 / 系统不支持，并给下一步。

**步骤 3 · 远端 DSH 探测与完成**

- 探测结果用「能力清单」展示，不让用户理解技术细节：
  - 系统：Linux x64 / Ubuntu 24.04（信息展示）。
  - 远端 DSH：已安装（版本 x.y.z）/ 未安装（可选：稍后自行安装）。
  - 远端界面：可启动 / 已在运行（可直接复用）/ 无法启动（显示原因）。
  - 模型凭据：已配置 / 缺失（提示在远端界面里配置）。
  - 远端宿主设置：检查是否会被误判为「本机工作站」（目录对话框 / Open In / 自动开浏览器），给出修正提示（详见 §15.2 P5）。
- 启动方式（若未运行）：由插件在远端启动界面服务（推荐）/ 用户提供已有地址与访问令牌 / 稍后手动处理。
- 完成：摘要 +「打开远程视窗」；失败可重试、可复制诊断、可保存为「未就绪」主机。

### 4.3 远程视窗（核心页面）

**目标**：在本地 DSH 里整页使用远端 DSH 的完整界面。

**两种呈现形态**（同一套内容，切换方式不同；DSH 全局面板能力见 §7.0）：

- **全局面板（V1 默认，推荐）**：插件注册一个「远程视窗」全局面板（与 DSH 自带「插件」页同一机制），选中后主区域整页显示远端 DSH 界面；左侧边栏保留主机列表与切换，顶部保留一条窄工具条（返回/切换/重连）。
- **沉浸模式（V1.1 可选）**：用 DSH 的 `shell.overlay` 全屏覆盖层，让远端界面铺满整个窗口，只留浮动工具条；适合长时间专注使用。

**窗口工具条内容**：

- 左：主机名 + 状态点（已连接/加载中/断线/错误）。
- 中：当前远端地址（可选隐藏）。
- 右：重连、刷新、切换主机（下拉）、沉浸模式开关、在新窗口打开、返回主机清单。
- 断线时工具条变为黄色并显示「连接断开，远端任务可能仍在运行」+ 重连按钮。
- 加载时显示进度与文案「正在连接 <主机>…」「正在打开远端 DSH…」。
- 错误时显示错误卡片 + 重试 + 诊断 + 返回。

**面板内容**：完全由远端 DSH 提供（会话、审批、文件、终端、插件、设置、凭据、日志都在里面）。本地不裁剪、不改写、不注入。

**关闭行为**：关闭视窗/切回会话 = 关闭本地承载，不结束远端任务；首次关闭时提示一次「远端任务会继续运行」。

### 4.4 连接状态与诊断

**入口**：主机卡片「诊断」、视窗工具条、设置页。

**内容**：一张检查表——SSH 可达性、认证方式、主机指纹、隧道状态、远端服务是否运行、远端界面是否可打开、远端 DSH 版本、模型凭据状态。

- 每项：通过/失败/未知 + 一句话说明。
- 操作：重新检查、复制诊断信息、查看最近连接日志（连接层，不含远端会话内容）。

### 4.5 设置

**窗口**：默认呈现形态（全局面板/沉浸模式/外部浏览器）、关闭视窗行为、是否记住最近视窗、是否允许新窗口打开。

**SSH 默认值**：默认端口、默认认证方式、默认跳板机、连接超时、自动重连开关与次数。

**安全**：主机指纹策略（首次询问/严格校验）、是否允许保存访问令牌（默认不保存）、密码策略说明。

**通知（P1）**：是否启用远端提醒、免打扰时段、是否显示远端任务完成提醒。

**其他**：语言、日志级别、导出/清理本地数据。

### 4.6 通知提醒（可选，P1）

- 触发：远端出现待审批 / 任务完成 / 远端会话报错（需用户在设置中开启）。
- 形式：本机通知 + 主机卡片标记；点击回到对应远端视窗（尽可能定位到对应页面）。
- 限制说明：这是本插件唯一需要"本地感知远端状态"的能力；V1 可先不做，保证"纯渲染"的简单性。

## 5. 核心流程

### 5.1 首次连接（目标 ≤ 3 分钟）

| 步骤 | 用户看到 | 用户做 |
|---|---|---|
| 1 | 主机清单空态 | 点「添加第一台服务器」 |
| 2 | SSH 表单 | 填地址/认证方式 |
| 3 | 连接进度 | 确认指纹 |
| 4 | 远端 DSH 探测结果 | 选择启动方式（默认推荐） |
| 5 | 远端 DSH 界面在「远程视窗」全局面板中整页打开 | 开始使用（后续操作都在远端界面里） |

### 5.2 日常打开

打开本机 DSH → 侧边栏「远程视窗」→ 点主机（或最近打开）→ 自动连接 → 主区域整页进入远端视窗。已连接过的机器目标 ≤ 10 秒。

### 5.3 断线与恢复

1. 网络中断/本机休眠：视窗工具条变黄，显示「连接断开，远端任务可能仍在运行」。
2. 自动重连（可配置）：恢复后刷新远端界面；断线期间远端任务不受影响（明确提示）。
3. 重连失败：显示错误分类与诊断入口，可手动重试。

### 5.4 多主机切换

- 工具条下拉切换主机；或侧边栏主机清单再点另一台。
- 每台主机独立视窗；同一主机可只保留一个视窗（可配置）。

### 5.5 远端服务未运行

本地探测到远端 DSH 界面服务未运行：提示「远端 DSH 未在运行」+「启动它」按钮；启动进度与结果在本地展示；成功后自动打开视窗。失败显示原因与诊断。

### 5.6 关闭与恢复

- 关闭视窗/退出本机 DSH：远端任务继续；下次打开直接回到主机（或最近视窗）。

## 6. 远端侧内容要求（产品视角）

- 远端只需**原版 DSH**（能提供 Web 界面即可），**不需要安装本插件的任何远端组件**。
- 远端界面默认只在本机可访问（经 SSH 隧道），不对公网暴露。
- 远端访问令牌：优先由插件在远端启动界面时自动获取；获取不到时允许用户手工粘贴已有地址与令牌。
- 远端版本：能提供 Web 界面的 DSH 版本即可；版本差异只影响远端界面本身，本地不感知具体功能。
- 启动方式会影响「桌面功能」判定：由 SSH 会话启动时 DSH 会关闭宿主桌面功能；由 systemd / 计划任务启动时可能误开（对话框弹在远端屏幕上）。插件默认经 SSH 启动远端界面，并在诊断里检查该状态。
- 可选（P2）：本地发起「安装/升级远端 DSH」，只在远端执行，本地展示进度与结果。

## 7. 呈现模式与能力依据

### 7.0 DSH 的「整页切换」能力（已确认，2026-11-10）

查证 DSH 0.2.2-rc.1 客户端布局包 `@deepseek-ai/dsh-client-ui-layout`（本地解包副本 `_research/asar2/...`）：

- **全局面板**占据 root 作用域的 `main` keyed slot；`conversation` 是为会话界面保留的 key；`ctx.layout.selectPanel(id)` 选中已注册面板、传 `null` 回到会话界面；DSH 自带「插件」页就是默认组合里的一个全局面板。
- **`shell.overlay`** 是覆盖整个框架的根级插槽，可做真正的全屏层。
- 已安装的 `dshmarket` 插件同时注册了 `main` 全局面板与 `sidebar.panellist` 侧边栏入口，并用 `ctx.layout.selectPanel(id)` 切换——这就是「整页切换」的现成用法。

结论：**整页切换可以做，且有两种粒度**——① 全局面板（主区域整页、保留侧边栏，V1 默认）；② `shell.overlay` 全屏覆盖（沉浸模式，V1.1 可选）。远端界面在面板内通过本地回环地址内嵌（同类插件 dsh-remote-gui 已采用 iframe 方案，本插件需在真机验收中逐项实测焦点/快捷键/新窗口/下载/剪贴板限制）。

### 7.1 模式对比

| 模式 | 本地要做什么 | 体验 | 主要限制 | 建议版本 |
|---|---|---|---|---|
| A 全局面板（整页） | 注册 main 面板 + 侧边栏入口 + 工具条 + 连接 | 主区域整页显示远端，侧边栏可切主机；最稳 | 左侧 DSH 侧边栏仍占一列 | **V1 默认** |
| B 沉浸模式（全屏覆盖） | 在 A 基础上加 `shell.overlay` 全屏层 | 远端界面铺满窗口，干扰最少 | 需要浮动工具条/退出入口；遮挡本地提示 | V1.1 可选 |
| C 原生渲染（真 VS Code 式） | 会话映射、事件回灌、审批桥、版本适配 | 最原生 | 本地工作量最大，与 DSH 内部契约耦合 | V2 评估 |

> 结论：V1 用 A；V1.1 加 B；C 只在确实需要原生体验且愿意投入时再做。

## 8. 交互与状态规范

### 8.1 主机状态

| 状态 | 含义 | 视觉 | 可操作 |
|---|---|---|---|
| 未配置 | 刚添加，未连接过 | 灰点 | 连接、编辑、删除 |
| 连接中 | 正在建立 SSH/隧道/打开界面 | 蓝点 + 进度 | 取消 |
| 已连接 | 远端界面可用 | 绿点 | 打开、断开 |
| 断线 | 连接丢失，可恢复 | 黄点 | 重连、诊断 |
| 错误 | 连接/认证/指纹/服务失败 | 红点 | 重试、诊断、编辑 |
| 受限 | 能连但远端无法提供界面（版本/配置问题） | 紫点 | 诊断、查看原因 |

### 8.2 视窗状态

加载中（分步骤文案）→ 已就绪 → 断线（banner）→ 重连中 → 已就绪；错误态为独立错误页，不显示空白视窗。

### 8.3 通知

- 连接成功/断开/重连：轻提示（toast）；断线时视窗内持续 banner。
- 主机状态变化：主机卡片即时更新。
- 可选远端提醒：本机通知 + 卡片标记（§4.6）。

### 8.4 错误文案（分类 + 下一步）

| 分类 | 标题示例 | 下一步 |
|---|---|---|
| 网络 | 「连不上这台服务器」 | 检查地址/端口/网络；跳板机先测跳板 |
| 认证 | 「SSH 认证没有通过」 | 检查用户名与密钥/Agent |
| 指纹 | 「主机指纹变了」 | 确认是否重装过服务器后再继续 |
| 远端服务 | 「远端 DSH 没有在运行」 | 点「启动它」，或查看诊断 |
| 远端界面 | 「远端界面打不开」 | 检查远端 DSH 版本与配置；复制诊断 |
| 版本 | 「远端 DSH 版本过旧」 | 在远端升级 DSH（V1.1 支持本地发起） |

### 8.5 危险操作（都在远端界面里，本地只做提示）

- 本地只负责：首次进入时提示「你正在操作远端服务器」；关闭视窗时提示「远端任务会继续运行」。
- 升级、插件安装、凭据修改等由远端界面自身确认，本地不重复拦截（避免双份规则不一致）。

## 9. 安全设计（用户可见部分）

1. **SSH 认证**：优先 SSH Agent/密钥；密码仅本次、不保存；首次连接确认主机指纹，指纹变化强提示。
2. **本地零暴露 + 回环硬规则**：远端界面只绑回环 + SSH 隧道；本地不监听公网地址。远端 DSH 的 cookie 是 `SameSite=Strict` 且按 authority 绑定，**跨 site 地址（公网域名 / Tailscale IP）嵌不进来**，必须映射为 `127.0.0.1:<本地端口>`（ssh -L，或 frpc 的 stcp/xtcp visitor）。
3. **访问令牌**：默认只在内存中使用，不落盘、不写日志；用户可在设置中允许保存（明确提示风险）。
4. **多主机隔离**：每台主机使用独立的本地端口/存储分区，登录态不串号（产品层面表现为：切主机不会串到另一台的界面）。
5. **信任边界**：本地视窗里显示的是远端 DSH 的界面，所有操作在远端执行；提示用户不要在本机视窗里向不可信远端粘贴敏感信息。
6. **全屏/内嵌限制**（V1.1）：明确指出内嵌界面的剪贴板、下载、外部链接行为可能受限；提供「在新窗口打开」作为逃生通道。

## 11. 版本与内容分期

| 版本 | 内容 | 退出标准 |
|---|---|---|
| V0 | 可行性闸门（2–3 天）：最小全局面板 + 回环 iframe，验证 cookie 种入 / 持久化 / 刷新；失败则确定「外部窗口打开」降级 | 5 项 V0 检查全绿（见调研文档 §5） |

| V1.1 | L8–L11（设置完善、沉浸模式、最近打开、多主机）、通知提醒、一键启动/安装/升级远端 DSH | 日常替代"手动 SSH + 浏览器"，多机可用 |

## 12. 与 v0.2「全控制台」方案的关系

| 维度 | v0.2 全控制台 | 本版薄客户端 |
|---|---|---|
| 本地工作 | 重做会话/审批/文件/终端/管理界面（7–9 周） | 只做连接/视窗/状态（1–2 周） |
| 能力覆盖 | 本地原生呈现，可深度集成 | 完全覆盖（= 远端 DSH 界面的全部能力） |
| 体验 | 更像本机应用 | 像"在本地整页里操作远端 DSH"（全局面板/沉浸模式） |
| 版本耦合 | 高（跟随 DSH 内部契约） | 低（只依赖 SSH 与远端界面存在） |
| 本地 agent 编排 | 支持 | 不支持（若需要，V2 加工具/桥接） |
| 通知/审计 | 可做完整 | 只做可选通知，无本地审计 |

**结论**：先用薄客户端满足「完全控制服务器上的 DSH」（控制 = 使用远端 DSH 自己的完整界面）；如果后续确实需要本机 agent 直接编排远端、或要求原生会话体验，再在该基础上渐进增强（通知桥 → 本地 agent 工具 → 原生渲染），而不是一上来重做一遍 UI。

## 15. 同类项目调研结论（2026-11-10）

调研了 8 个 DSH 远程类项目（dsh-remote-dsh、dsh-remote-gui、dsh-remote-tunnel、dsh-remote-explorer、dsh-remote-local-plugin、dsh-zen-remote、dsh-ssh-desktop、dsh-multi-instance）与 3 个邻近产品。完整报告与证据见 `_design/research/同类项目调研与需求注意点.md`。

### 15.1 对需求的增补（进入 V1）

| 增补 | 理由 |
|---|---|
| SSH 别名自动发现（`~/.ssh/config`；`known_hosts` 只读且跳过哈希条目） | dsh-remote-tunnel 证明这是降低接入摩擦的关键；哈希条目无法反解，只报数不猜 |
| 远端宿主检查：桌面功能干扰项 + 启动方式建议 | systemd 启动的远端会被 DSH 当作「本机工作站」，目录对话框/Open In 弹在远端屏幕；dsh-remote-dsh 用 5 组配置修正 |
| 隧道「收养」与去重 | 本机重启后复用还在监听的隧道，避免重复 spawn；dsh-remote-gui / ssh-desktop 都做了 |
| 诊断导出默认脱敏、token 只在内存、主机注册表不含凭据 | dsh-ssh-desktop 的诊断脱敏、dsh-remote-gui 的 cookie 内存缓存是成熟做法 |
| 入口在空会话也可用（侧栏 + 全局面板） | dsh-remote-tunnel 的命令卡/状态条在空会话不渲染，侧栏面板才是保底入口 |

### 15.2 必须避开的坑（Top 8）

| # | 坑 | 我们的动作 |
|---|---|---|
| P1 | **回环硬规则**：`SameSite=Strict` 硬编码，公网域名 / Tailscale IP 的 iframe 连 index 都 401 | 只接受 `127.0.0.1:<端口>`；非回环地址当场警告并给出替代方案 |
| P2 | **iframe cookie 种入/持久化未验证**（dsh-remote-gui 因此改为原生面板） | V0 闸门先验证；失败就用「在新窗口打开」正式降级 |
| P3 | **token 发现依赖 systemd unit 名**（`dsh-web`） | 插件自己接管远端 web 的启动并解析 stdout；兜底用户粘贴 URL+token |
| P4 | **嵌套实例**：把本机实例嵌进面板 → 套娃卡死 | 默认目标永远远端；本地模式不嵌 iframe |
| P5 | **远端桌面功能误开**：对话框/Open In 出现在远端屏幕 | 经 SSH 启动远端界面（带 SSH 环境信号）；诊断检查 5 组配置 |
| P6 | **契约漂移**：RPC args key 因方法而异（`session/list` 是 `_request`）、流式必须走 WS、HTTP 200 也可能是失败 | 只依赖少量端点；集中适配；看 `result.ok`；能力探测 |
| P7 | **会话噪声与归档非权威**：346 条里 317 条子代理；归档只是本机视图 | 交给远端 GUI 自己处理；不在本地伪造状态 |
| P8 | **token/文档风险**：profile 里存 token 的警告；README 与代码漂移 | token 默认不落盘；文档只写「已验证」的事实，发布前实测 |

### 15.3 结论

- 方向成立：dsh-remote-dsh 证明「回环 + 整页嵌入远端 GUI」可行；dsh-remote-gui 证明「本地只管隧道/凭据、界面交给远端或重写」两条路都存在。
- **最接近的现成实现是 `graydovee/dsh-remote-window`（alpha.6）**：已用**同源 portal 反代**解决 iframe cookie，主区全屏显示远端官方 UI，支持本机模型自动代理 / server 模型、host key pin、per-client profile 与 runtime；代价是远端更重（常驻 profile + 专属插件 + 独立 runtime）。详见 `_design/research/dsh-remote-window-调研.md`。
- 因此自研只剩两条路：**轻量差异化**（零远端专属组件、只用远端已有 dsh web + SSH，自己做 portal 或接受外部窗口降级）或 **fork/采用**该实现。
- 最大风险仍是 **iframe 的 cookie 种入/持久化**：必须 V0 先验；已有 portal 正解可参考。

## 16. 远端自举与运维管理（v0.6 增补）

> 吸收同类项目设计 + 用户新增需求：远端无环境也能起 DSH、远端版本与本机一致、本机关闭后远端可继续存活（可配置）、远端插件与设置可在本机管理。

### 16.1 新增内容清单

| 编号 | 内容 | 说明 | 优先级 |
|---|---|---|---|
| L13 | 远端环境自举 | 优先 `npx` 拉起目标版本 DSH；无 Node 时下载独立 Node 运行时；无网络时用客户端离线包 | P0 |
| L14 | 版本一致性 | 目标版本 = 本机 DSH 版本；不一致时明确提示并给出升级/沿用/取消选项，不静默混用 | P0 |
| L15 | 远端存活策略 | 关闭本机后远端可继续运行（默认）/ 退出即停 / 空闲 N 分钟后停，按主机可配 | P0 |
| L16 | 远端插件管理 | 在本机列出/安装/启用/禁用/卸载/更新远端 DSH 插件 | P1 |
| L17 | 远端设置管理 | 在本机读取/编辑远端常用设置，保存前 diff、备份、校验，按需重启远端服务 | P1 |

### 16.2 远端自举分级（从轻到重）

| 级别 | 远端现状 | 做法 | 用户看到 |
|---|---|---|---|
| T0 | 已有**同版本** DSH | 直接复用，只补启动/隧道 | 「已就绪」 |
| T1 | 有 Node + npx | `npx -y @deepseek-ai/dsh@<本机版本>` 拉起 web profile（不全局安装，缓存可复用） | 预计 1–3 分钟，显示下载/启动进度 |
| T2 | 有 Node 但 npx 受限 | 用 npm/pnpm 把目标版本装进远端隔离目录（`~/.dsh/remote-window/runtime`），再用绝对路径启动 | 明确显示「安装到用户目录」 |
| T3 | 无 Node | 下载官方 Node 压缩包到用户目录（校验 SHA-256，无需 root），再用 T1/T2 | 显示 Node 版本与校验结果 |
| T4 | 无网络/受限网络 | 使用客户端内置的离线包（Node + DSH），或让用户提供镜像/代理 | 显示「离线安装」来源 |
| T5 | 连 curl/tar 都没有（极简容器） | 不假装能装：给出可复制的准备命令，或说明需要在镜像层面解决 | 明确失败原因与下一步 |

**原则**：`npx` 是「轻」路径而不是唯一路径；任何一级失败都要停在**可解释、可重试**的状态，不静默降级。

### 16.3 版本一致性

- 目标版本**取自本机 DSH 版本**（例如 `0.2.2-rc.1`），而不是 npm 的 `latest`；安装时写精确版本。
- 远端已装但版本不同：默认**不直接使用**，弹窗给出「升级到本机版本 / 使用现有版本（标注不保证 UI 一致）/ 取消」。
- 版本比对用闭区间/精确版本判定（参考 `dsh-remote-window` 的 `compat/runtimes.json` 思路），不假设「更高即可」。
- 本机升级后，已连接主机的版本不一致要在主机卡片上提示「建议同步远端版本」，可一键升级。
- 远端插件/设置管理都按目标版本语义执行；版本不一致时禁用管理入口并说明原因。

### 16.4 本地关闭后的远端存活（可配置）

| 策略 | 行为 | 适用 |
|---|---|---|
| 保持运行（默认） | 关闭本地窗口/退出后，远端 DSH 与任务继续；下次连接直接复用 | 长任务、服务器常驻 |
| 退出即停止 | 正常退出时停止远端服务并清理隧道 | 临时使用、按量计费 |
| 空闲停止 | 本机断开后空闲 N 分钟自动停止（可配 5–60 分钟） | 平衡成本与体验 |

- 按主机配置，首次关闭时提示当前策略并允许切换。
- 异常退出（崩溃/断电）：远端不应被立刻杀；由租约/心跳判断，超过阈值后才按策略清理（不做「客户端一断就杀」）。
- 服务托管：优先 systemd user unit（无 root、可 `linger`），不可用时用 nohup/pidfile；停止/升级要显示影响（运行中的 turn 会取消）。
- 关闭本地时若有运行中任务，提示「远端会继续运行，下次打开可接续」或「将停止远端并中断任务」。

### 16.5 远端插件管理（本机操作）

- 入口：主机详情 →「DSH 管理」→ 插件。
- 列表：名称、版本、启用状态、更新可用性、来源（npm/tarball/GitHub）、最近安装时间。
- 操作：安装（包名 + 精确版本 / tarball 路径或 URL）、启用/禁用、卸载、更新；显示兼容性与「需重启远端 DSH」标记。
- 安全：两次确认 + 影响说明（插件可能执行远端命令）；安装前校验包名/版本可与目标 DSH 版本兼容；失败展示远端原始错误并提供复制。
- 不显示本地插件（本机已有自己的插件页）；不通过本地插件影响远端无关进程。
- 参考：`dsh-remote-explorer` 选择「远端插件由远端自管」，我们反其道做本机管理，作为差异化；`dsh-remote-window` 已有本机写远端 profile 配置的先例。

### 16.6 远端设置管理（本机操作）

- 入口：主机详情 →「DSH 管理」→ 设置。
- 常用项可视化（默认模型、权限预设、上下文/压缩、通知、插件配置等）；高级项只读 + 受控编辑。
- 保存流程：**读取 → 编辑 → diff 预览 → 校验 → 备份 → 写入 → 按需重启**；失败自动回滚备份。
- 明确标注「仅影响远端」；与远端界面同时修改时以远端为准并在保存前检测冲突。
- 版本不一致或远端不支持该设置项时隐藏/置灰，并说明原因。

### 16.7 页面与流程改动

- **主机详情**新增 Tab：「概览 / 服务 / DSH 管理（版本/插件/设置/凭据/日志）/ 连接」。
- **接入向导第 3 步**从「探测结果」扩展为「自举方式选择」：默认推荐（T0/T1）、展开高级（T2/T3/离线），并显示目标版本与本机版本是否一致。
- **关闭流程**：关闭视窗/退出时按主机策略提示（保持运行/停止/空闲停止），不静默改变行为。
- **管理流程**：插件安装/卸载、设置保存都有「diff/影响 → 确认 → 执行 → 结果」四步，操作进审计。

### 16.8 安全与权限（增补）

- 自举命令只使用**白名单模板**（Node 下载、npx 精确版本、npm/pnpm 安装），不接受用户拼接的任意 shell。
- npx/安装使用精确版本号；下载 Node 校验 SHA-256；离线包校验哈希；失败不静默降级。
- 插件安装、设置写入、服务重启都是高权限操作：二次确认 + 影响说明 + 审计；多用户共享主机时明确「操作的是该 SSH 账号的环境」。
- 设置写入前备份（0600），保留最近 N 份；写入失败回滚。
- 远端服务默认只绑 `127.0.0.1`，经 SSH 隧道访问；token 仅在内存/0600 文件。

## 附录 · 5 分钟演示脚本

1. 本机 DSH → 侧边栏「远程视窗」→ 空态 →「添加第一台服务器」。
2. 填 SSH 别名 → 指纹确认 → 探测到远端 DSH 已安装 →「打开远程视窗」。
3. 主区域整页切换到远端 DSH 界面，工具条显示主机名与绿点；左侧边栏保留主机清单。
4. 在远端界面里新建会话、发消息、处理审批、打开文件与终端（全部是远端能力）。
5. 断网 30 秒：工具条变黄提示「远端任务可能仍在运行」；恢复后自动重连。
6. 切回主机清单，添加第二台，切换验证互不影响。
